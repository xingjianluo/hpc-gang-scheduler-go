# hpc-gang-scheduler-go

进程内的 HPC 整组（gang）作业调度组件。用模拟节点与资源池代替真实集群，
不依赖任何外部集群服务或凭据，覆盖 **整组调度、配额、优先级抢占、资源回填、
任务重试、执行超时、节点失联恢复** 完整链路。

## 结构

```
scheduler/            核心调度器包
  types.go            作业/任务/资源/事件等类型定义
  node.go             模拟计算节点（容量 + 已用账本）
  scheduler.go        提交校验、整组调度、抢占、回填、事件处理、恢复
  store.go            JSON 快照持久化（临时文件 + rename 原子写入）
  scheduler_test.go   整组拒绝 / 并发竞态 / 抢占 / 节点失联重复事件 / 恢复测试
cmd/demo/             本机可运行的端到端演示
```

## 调度语义

- **整组（gang）调度**：一个作业（`Count>1` 即作业数组）的全部任务必须在同一轮
  调度中都找到节点才一起启动；放不下就整组留在队列，绝不部分启动占用资源。
- **整组拒绝**：提交时校验失败即整组拒绝，原因可区分（`RejectReasonOf(err)`）：
  - `DUPLICATE_SUBMISSION`：同一 `JobID` 重复提交；
  - `QUOTA_EXCEEDED`：提交方在途资源（排队+运行+待重放）加上新作业超出配额；
  - `RESOURCE_NEVER_FITS`：单任务需求超过所有节点容量（永远调度不上，直接拒绝）。
- **队列排序**：优先级数值大者优先，同级按提交时间先到先排。
- **回填**：队首作业整组放不下时跳过它继续看后面的作业，小作业可以穿插启动。
- **单任务重放**：运行中作业里失败重试 / 被抢占 / 节点失联重入队的任务，
  在每轮调度开始时按优先级单独安置（`REPLACE` 日志）。

## 配额与抢占规则

- 配额按提交方（`Owner`）计，统计该方所有未终态作业中未终态任务的资源总和；
  提交时 `已在途 + 新申请 > 配额` 即整组拒绝。
- 高优先级作业整组放不下时，从 **优先级严格更低且标记 `Preemptible`** 的运行中
  任务里按优先级从低到高挑选受害者；**只有抢占后整组确实能放下才真正驱逐**，
  否则不做无谓抢占（试算失败会回滚账本）。
- 被抢占任务回到待调度状态（`PREEMPTED`），节点账本同步归还，不消耗重试次数；
  资源空出后在后续调度轮次自动回填。
- 一个任务彻底失败（重试次数耗尽或超时）即整组终止：其余任务被杀、资源释放，
  作业进入 `FAILED`。

## 事件与状态恢复

- 外部事件（任务完成 / 节点失联 / 节点恢复）允许 **重复或乱序** 到达：
  - 已到终态的任务收到完成通知直接忽略，不重复计数；
  - 非 `RUNNING` 状态任务（如节点失联后已重入队）的迟到通知按 stale 忽略；
  - 重复的节点失联/恢复事件幂等。
- 节点失联：节点标记不可用、账本清零，其上运行中的任务重入队（不占重试次数）；
  节点恢复后重新参与调度。
- 执行超时：`ExecTimeout>0` 的任务超时时按失败处理（走重试/整组终止逻辑）。
- 持久化：每次状态变更后把作业与节点账本快照原子写入 `Store`；
  进程重启后 `Recover()` 从快照恢复——运行中的任务保持运行、排队作业重新入队，
  调度从断点继续而不是从头开始。

## 并发安全

所有导出方法共用一把互斥锁，并发提交、并发调度、并发事件下同一资源不会被
重复分配；测试在 `-race` 下验证账本永不超过节点容量、账本与运行任务占用一致。

## 本地验证

```bash
go build ./...          # 编译
go test ./...           # 单元测试（日志含调度决策与资源账本快照）
go test -race ./...     # 竞态检测
go test -run TestPreemptionAndBackfill -v ./scheduler/   # 查看单个场景的决策日志
go run ./cmd/demo       # 端到端演示：提交→抢占→节点失联/恢复→回填→状态恢复
```
